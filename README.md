# 🎭 演出提示单（Cue Sheet）· 小剧场排练用

基于 **Node.js / Express + 原生 HTML/CSS/JavaScript** 的单页小工具，无任何前端构建与框架。
每条演出提示（Cue）记录：

- **名称**
- **独占设备通道**（如：灯光台 A、追光 B、调音台 M）
- **持续秒数**
- **开始时间**，二选一：
  - 固定：从演出开始的第 N 秒；
  - 相对：在**另一条提示结束后**延迟 N 秒开始。

新增 / 修改提示后，服务端会**递归重算所有后继提示**的开始与结束时间；时间轴按
**左闭右开 `[开始, 结束)`** 区间绘制，自动标出同一通道上互相重叠的提示及**冲突时段**。
首尾相接（前一条结束时刻 = 后一条开始时刻）不算冲突。**冲突允许保留**，仅作排练现场调整的提醒。

数据保存在本地 JSON 文件（默认 `./data/cues.json`），原子写入（先写临时文件再 rename）。

**冲突顺延预演**：在「通道冲突」面板中可对任一冲突提示发起顺延预演 —— 在不提前其原开始时刻的前提下，
把它顺推到所在通道的**最早完整空位**（遇占用推到该占用结束，首尾相接可用）；固定开始提示改固定秒数，
相对开始提示只增加延迟秒数，后继提示随调度器重算。预演列出被顺延的提示、前后时刻及新增/消失的冲突，
**确认前不写入**；确认时服务端重新核对预演所依据的提示单版本，已变化则拒绝并要求重新预演，未变化才原子保存。

**片段排练单**：输入原演出时间窗 `[起, 止)`（左闭右开，秒），可在页面预览片段时间轴与通道冲突，
并下载一份**可独立使用**的 JSON 提示单（时间已平移到从 0 开始）；原提示单不会被修改。
生成规则见下文「片段排练单」一节。

**单次排练 · 实况执行台**：点击「开始排练」即**冻结当前全部提示与重算计划**（开始后再增删改提示单不影响本轮），
按**演出秒数**逐条登记每条提示的实际开始 / 结束；登记实时持久化到独立 JSON，**刷新页面、重启服务后可继续登记**。
开始登记必须同时满足调度规则（前置已结束且达到「前置实际结束 + 延迟」、固定提示达到固定秒数、本通道无进行中提示、
不早于本通道最后一次结束），页面会明确列出每条提示被阻止的原因；结束秒数不得早于开始秒数。
「重置」清除本轮冻结与全部登记，可开启新一轮，**不会修改原提示单**。规则详见下文「实况执行台规则」一节。

## 一条命令启动（Docker Compose）

依赖安装（镜像构建时 `npm install`）与数据初始化（首次启动自动写入示例 JSON）都包含在这一条命令里：

```bash
docker compose up -d --build
```

启动后访问：

> **http://localhost:3000**

停止：

```bash
docker compose down
```

> 首次启动若宿主机 `./data/cues.json` 不存在，会自动创建 `data/` 目录并写入一组示例提示
> （其中故意包含一对同通道重叠提示，用于展示冲突标记）。之后所有增删改都持久化到该文件。
> 排练实况记录保存在同一目录的 `./data/rehearsal.json`（开始排练时生成，重置时删除），与提示单互不影响。

## 必要配置

均为**可选项**，不配也能直接跑（使用下面的默认值）：

| 配置项 | 位置 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 宿主机访问端口 | `docker-compose.yml` 环境变量 `HOST_PORT` | `3000` | 例如 `HOST_PORT=8080 docker compose up -d --build` 后访问 http://localhost:8080 |
| 数据文件路径 | 容器内环境变量 `DATA_FILE` | `/app/data/cues.json` | JSON 落盘位置；Compose 默认把宿主机 `./data` 挂载到该目录 |
| 排练记录文件路径 | 容器内环境变量 `REHEARSAL_FILE` | `/app/data/rehearsal.json` | 单轮排练冻结计划与实际登记的落盘位置；默认与提示单在同一挂载目录 |
| 容器监听端口 | `PORT` | `3000` | 一般无需修改；改了需同步调整端口映射 |

需要自定义时，可在项目根目录创建 `.env`，例如：

```env
HOST_PORT=8080
```

## 使用说明

1. **新增提示**：在「新增提示」表单填写名称、独占通道、持续秒数，选择开始方式（固定秒数 / 另一提示结束后延迟），点击「保存新增」。
2. **编辑提示**：点击时间轴上的色块，或列表中的「编辑」。修改保存后，所有后继提示立即重算，时间轴即时刷新。
3. **冲突处理**：同通道重叠的提示块变红，时间轴上以红色斜纹标出**冲突时段**，下方「通道冲突」面板列出重叠的秒数区间。冲突**不会阻止保存**，可保留供排练调整；首尾相接不算冲突。
4. **冲突顺延预演**：在「通道冲突」面板中点击「顺延『某提示』」，即可预演把该提示顺推到本通道最早完整空位：预演面板列出被顺延的提示（含随重算的后继）前后时刻、新增/消失的冲突；确认无误后点「确认顺延并保存」才写入。若预演后提示单被他人/他处改动，确认会被拒绝（HTTP 409），需重新预演。规则详见下文「冲突顺延预演规则」。
5. **删除提示**：若仍有其他提示以它为前置，会被拒绝（HTTP 409）并提示具体引用者，需先调整这些提示，避免产生悬空引用。
6. **片段排练单**：在「✂️ 片段排练单」面板输入原演出时间窗 **[起, 止)**（左闭右开，秒），点击「生成预览」即可看到片段时间轴、片段冲突与入选清单；确认无误后点击「下载片段 JSON」得到一份独立提示单。原提示单发生增删改后旧预览会标记失效，需重新生成。
7. **单次排练实况**：在「🎬 单次排练 · 实况执行台」点击「开始排练」冻结当前计划；在顶部填写**当前演出秒数**，各行的「登记开始」按钮会据此启用/禁用并列出被阻止原因；进行中的提示用同一秒数「登记结束」。刷新页面或重启服务后数据仍在，可继续。点击「重置」清除本轮记录后可按最新提示单再开新一轮（原提示单不变）。

### 实况执行台规则

- **冻结**：开始排练时对当前提示单全量重算并复制一份快照（名称、通道、持续、开始方式、计划开始/结束）。冻结后即便在页面上增删改提示，本轮仍按快照执行；页面顶部会提示「原提示单已被修改」，重置后再开始才会使用最新计划。
- **开始登记条件（必须全部满足，否则拒绝并逐条列出原因）**：
  - **固定开始**提示：实际开始秒数 ≥ 固定秒数；
  - **相对开始**提示：其前置提示**本轮已登记实际结束**，且实际开始 ≥ 前置实际结束 + 延迟秒数；
  - 本通道当前**没有进行中**（已开始未结束）的提示；
  - 实际开始**不早于本通道最后一次实际结束**（按已登记的实际结束取最大值）。
- **结束登记条件**：该提示已登记实际开始；实际结束秒数 **≥ 实际开始秒数**，否则拒绝。
- **没有自动时钟**：所有时刻均为操作员手动录入的「演出秒数」（支持小数），因此跨通道的提示可以并行登记，通道内先后由上述规则保证。
- **状态与偏差**：每条提示按冻结的计划时间展示 ⏳ 未开始 / 🔴 进行中 / ✅ 已完成，以及
  开始偏差 = 实际开始 − 计划开始、结束偏差 = 实际结束 − 计划结束（正为延后、负为提前）。
- **阻止原因可见**：未填秒数时也会显示与秒数无关的原因（前置未结束、本通道忙）；填入秒数后立即按该秒数重新判定（只读刷新，不会登记）。
- **持久化与继续**：每次登记都原子写入 `rehearsal.json`（临时文件 + rename）；刷新页面或重启服务会自动载入未结束的一轮并保留全部登记。
- **前置条件**：提示单存在时间未定的提示（悬空引用/循环依赖）时不允许开始排练（HTTP 400），需先在提示单中解决。
- **重置**：只删除本轮排练记录文件，**原提示单不做任何修改**。

### 冲突顺延预演规则

- **空位搜索**：以该提示现有重算开始时刻为下界（**不提前**），在其独占通道上找最早能完整容纳其持续秒数的起点；遇到占用区间就推到该占用的**结束时刻**继续找，首尾相接（前一条结束 = 后一条开始）视为可用。
- **障碍集合**：只统计同通道、时间已定的**其他**提示；该提示的**后继**（直接或间接以它为前置）不作为障碍 —— 它们会随调度器一起重算移动。
- **应用方式**：固定开始提示把 `fixedAt` 改为新开始时刻；相对开始提示保持前置不变，**只增加** `delayAfter`（增加量 = 顺推秒数），因此新开始时刻绝不会早于原开始时刻。
- **预演结果**：列出全部被顺延的提示（目标 + 时刻变化的后继）的前后开始/结束、按（通道 + 提示对 + 区间）判定的新增/消失冲突；预演**只读**，不落盘。
- **确认保存**：确认时服务端重新计算提示单版本（内容哈希）并与预演依据的版本比对，**不一致则拒绝（HTTP 409）并要求重新预演**；一致才把调整应用到目标提示并原子写入（临时文件 + rename），全部后继随现有调度器重算。
- **明确反馈**：提示时间未定（悬空引用/循环依赖，HTTP 400「无效时间」）、提示不存在（HTTP 404）、通道无可用空位（HTTP 400）都会在页面上给出明确提示；当前位置已无冲突时预演会提示「无需顺延」且不显示确认入口。


### 片段排练单规则

- **选取**：按原提示单现有重算时间，选出与窗口有**正长度交集**的提示；仅在端点相接（如结束时刻 = 窗口起点）不计入。
- **截取与平移**：每条入选提示的区间先截到窗口 `[max(原开始, 起), min(原结束, 止))`，再整体减去窗口起点，片段时间轴从 **0** 开始。
- **开始方式改写**：
  - 原本相对开始的提示，若其**前置提示未入选**，或本提示**跨过窗口左边界**（原开始早于窗口起点），改为**固定开始**（固定秒数 = 截取后起点）；
  - 其余相对关系在片段内平移后仍然成立，**原样保留**（含延迟秒数）；
  - 持续秒数按截取后的区间长度重算，保证重新计算的开始/结束时刻与截取结果完全一致。
- **独立性**：下载文件为 `{ "cues": [...] }` 结构（与本地数据文件同构，另带 `fragment` 元信息），**无任何悬空引用**，可直接作为另一个实例的数据文件使用。
- **冲突**：预览中的「片段通道冲突」由同一套**左闭右开**规则在平移后的时间上计算。
- **报错**：窗口非法（非数字、负数、止 ≤ 起等，HTTP 400）或原提示单存在**时间未定**的提示（悬空引用/循环依赖，HTTP 400）时明确拒绝，并给出具体原因。


### 校验与拒绝规则

- 名称 / 通道不能为空，持续秒数、固定秒数、延迟秒数必须为非负数；
- 相对开始引用的提示必须存在，否则**拒绝保存**；
- 不允许把自己设为前置；任何**循环依赖**（含多节点环）都会被检测并**拒绝保存**，已在环上的提示在页面上标记为「时间未定」；
- 保存采用全量校验：新数据有问题时整次写入回滚，磁盘上的数据不受影响。

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/cues` | 返回全部提示、重算后的时间表 `schedule`、冲突 `conflicts`、图错误 `graphErrors` |
| `POST` | `/api/cues` | 新增提示并全量重算；引用/环问题返回 400 |
| `PUT` | `/api/cues/:id` | 修改提示并重算所有后继；非法修改返回 400 并回滚 |
| `DELETE` | `/api/cues/:id` | 删除提示；仍被引用时返回 409 |
| `POST` | `/api/deferrals/preview` | 顺延预演（只读）：body 为 `{"cueId": "..."}`；返回应用方式 `adjust`、被顺延提示 `moved`（前后时刻）、`conflictsAdded` / `conflictsRemoved` 及版本 `baseVersion`；时间未定/无空位返回 400，提示不存在返回 404 |
| `POST` | `/api/deferrals/confirm` | 确认顺延：body 为 `{"cueId": "...", "baseVersion": "..."}`；版本与当前提示单不一致返回 409（需重新预演），一致才应用调整并原子保存，返回重算后的完整快照 |
| `POST` | `/api/fragments/preview` | 预览片段：body 为 `{"start": 起, "end": 止}`；返回截取后的 `cues`、重算 `schedule`、`conflicts`、改写说明 `changes` 与待下载的 `document`；窗口非法或源提示时间未定时返回 400 |
| `GET` | `/api/fragments/download?start=起&end=止` | 直接下载片段 JSON（`Content-Disposition: attachment`）；错误同样返回 400 |
| `GET` | `/api/rehearsal?at=秒` | 单次排练实况：无进行中一轮时返回 `{"active": false}`；有则返回冻结快照视图（每条提示状态、计划/实际时刻与偏差）。可选 `at` 为当前演出秒数，服务端据此返回每条未开始提示的阻止原因 `blockers`；不带 `at` 只返回与秒数无关的原因 |
| `POST` | `/api/rehearsal/start` | 开始一轮排练并冻结当前计划；已有进行中一轮返回 409；提示单存在时间未定的提示返回 400（`reasons` 列出具体问题） |
| `POST` | `/api/rehearsal/cues/:id/start` | 登记实际开始：body 为 `{"at": 秒}`；不满足任一调度规则或秒数非法返回 400，`error.reasons` 给出**全部**阻止原因（`before_fixed` / `predecessor_open` / `before_predecessor_end` / `channel_busy` / `before_channel_last_end` 等）；未开始排练返回 409 |
| `POST` | `/api/rehearsal/cues/:id/end` | 登记实际结束：body 为 `{"at": 秒}`；未先开始、重复结束或结束早于开始返回 400（`end_before_start` 等）；未开始排练返回 409 |
| `POST` | `/api/rehearsal/reset` | 重置：删除本轮冻结快照与全部实际登记（排练记录文件），**不修改原提示单**；返回 `{"ok": true, "active": false}` |
| `GET` | `/healthz` | 健康检查 |

片段接口均为**只读**：不会修改、持久化原提示单。顺延接口中仅 `confirm` 在版本核对通过后写入；`preview` 同样只读。
排练接口的 `start` / `cues/:id/start` / `cues/:id/end` 只写入排练记录文件 `rehearsal.json`，**任何情况下都不改动 `cues.json`**；`reset` 仅删除该排练记录文件。


提示对象示例：

```json
{
  "name": "第一幕追光",
  "channel": "追光 B",
  "duration": 20,
  "startType": "after",
  "afterCueId": "cue-a1",
  "delayAfter": 5
}
```

`startType: "fixed"` 时使用 `fixedAt`（固定开始秒数），`afterCueId` 传 `null`、`delayAfter` 传 `0`。

## 项目结构

```
.
├── Dockerfile
├── docker-compose.yml
├── package.json
├── server/
│   ├── index.js       # Express 路由 + 静态文件服务（含顺延预演/确认、片段预览/下载、排练实况接口）
│   ├── scheduler.js   # 引用/循环校验、时间递归重算、左闭右开冲突检测
│   ├── defer.js       # 冲突顺延预演：最早空位搜索、计划生成、提示单版本核对
│   ├── fragment.js    # 片段排练单：窗口校验、选取、截取平移、依赖改写、一致性自检
│   ├── rehearsal.js   # 单次排练实况：冻结计划、开始/结束条件校验、状态与偏差视图
│   └── store.js       # 本地 JSON 存取：提示单初始化 + 排练记录文件的原子读写/清除
├── public/
│   ├── index.html
│   ├── styles.css
│   └── app.js         # 原生 JS：时间轴、冲突面板、顺延预演/确认、编辑表单、片段预览下载、排练实况执行台
└── data/
    ├── cues.json        # 运行后自动生成（被 .gitignore 忽略）
    └── rehearsal.json   # 开始排练后生成（重置时删除，同样被 .gitignore 忽略）
```
